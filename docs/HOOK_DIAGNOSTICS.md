# Диагностика хуков без повторения круга

В исходном архиве пользователя найдено 57 событий с корректной цепочкой хешей.
Это подтверждает, что прежний захват в Windows в итоге работал. Это не означает,
что новый релиз уже проверен на той машине или что закрыты все случаи J0.

1. Определение найдено? На предоставленных снимках правильный вход — значок
   хуков под полем ввода, открывающий «Проверка хуков». Поиск Settings → Hooks
   в той версии интерфейса не помогал. Проверьте открытый проект и hooks.json.
2. Доверена текущая команда? Разверните Digital Trace v2, проверьте Python, dt.py
   и каталог captured. Доверие проекту не заменяет доверия определению hook.
   Изменение определения требует повторного рассмотрения.
3. Есть попытка запуска? После одного нового сообщения выполните doctor и
   проверьте записи hook/started и hook/completed в журнале приложения. Если
   попыток нет, исправление парсера payload не решит проблему запуска.
4. Есть ошибка исполнения? Проверьте captured/hook_errors.log, существование
   Python и абсолютные пути. Ошибка самого запуска Python может быть только
   в журнале приложения. Установщик создаёт commandWindows с корректным
   экранированием, без лишних обратных слешей вокруг кавычек.
5. Конфигурация новее процесса? Только если это подтверждено, полностью выйдите
   через «Файл → Выйти из ChatGPT» и откройте проект. Закрытие окна может оставить
   фоновый процесс. Если это не помогло, нужны версии и логи, а не новые циклы
   одинаковых перезапусков.

## Фактический контроль

Помощник один раз выполняет `python tools/j0_probe.py prepare --workspace workspace`.
Prepare не создаёт событий. Пользователь отправляет выданное точное сообщение,
получает указанный ответ, затем отправляет запрос на stdout/stderr с exit code 3.
После этого помощник выполняет `python tools/j0_probe.py check --workspace workspace`.

Проверка связывает маркер, ответ и результат инструмента с той же сессией.
SessionStart может находиться до prepare; проверка это учитывает. Синтетические
фикстуры не дают passed. Даже basic_probe=passed не сертифицирует полный J0:
прерывания, fork, compaction и длинный диалог проверяются отдельно.

Исходные байты хранятся в capture.sqlite3; JSONL — восстанавливаемые представления.
После сбоя проекции следующий hook восстанавливает их из базы. Полный Stop не
гарантирует все промежуточные сообщения ассистента. Пробелы не заполняются пересказом.
Текущий коллектор перепроверяет цепочку и пересобирает проекции на каждом событии;
это удобно для контролируемого пилота, но длинные сессии требуют нагрузочного теста.
